# Exo code study: what the repo confirms, what it contradicts

*2026-08-24 · exoharness/exo @ `9606566` (main, committed 2026-08-19; shallow clone) · MIT · ~65k LOC Rust core (exoharness 30.4k, executor 20.9k, cli 12.5k) + TypeScript agent layer · read against piko's ADRs · provenance appendix at the end*

## Verdict

The architecture from the podcast is real and, in places, more serious than advertised — Firecracker microVMs, a seven-provider sandbox matrix, drain-based service restarts, a genuinely honest self-assessment doc. But the safety headline does not survive contact with the code: **in the canonical local setup, the "immutable" event log is bind-mounted read-write into the agent's own sandbox, is protected by convention, and is not fsynced.** Meanwhile there are no hard run budgets anywhere — cost is measured, never bounded. Every critique we made from the podcast is confirmed by the source, twice over by their own documentation.

## Confirmed by the code

- **The three layers exist as described**, with an elegant twist the podcast never mentioned: the split is expressed in *language* — the protected mechanism layer is Rust; the evolvable agent/policy layer is TypeScript. The durable/ephemeral line is a compile boundary.
- **Sandbox provider matrix**: local Docker, **Firecracker microVMs** (with real engineering — fsync'd image handling, claim files), Daytona, E2B, Sprites, Vercel, AWS AgentCore. This is ahead of piko's roadmap checkbox by a full generation.
- **The guardian is real ops engineering**: deferred rebuilds recorded under `.exo/guardian-updates/`, drain markers instead of blind kills, process-group termination for adapter workers, reboot notices with a durable outbox. Outcomes are appended to the event log as host events.
- **Secrets got the care**: a dedicated store (`secrets.rs` — the *only* storage path with `sync_all`), keychain backend, fetched by executor code and injected at use — the model is not ambient with keys. Matches ADR 0016's walls.
- **Event log content is rich**: sessions, turns, messages, tool requests/results, errors, artifact writes, sandbox lifecycle, host events (`host_reboot`, `adapter_runner_started`, drains, rebuild outcomes). Rewind restores filesystem only — history survives, and git is explicitly the second log.
- **Culture kin to piko's**: `SELF-CONTROL.md` states design principles and then lists its own gaps by name; there's CI, integration tests, 29 test files, a fuzz target (Firecracker protocol). These are people who write down what's missing.

## Contradicted by the code (with receipts)

**1. "The only thing it can't muck with is the event log" — false in the canonical setup.**
`exo.sh:647` mounts the *entire repo root* read-write into the shared agent sandbox: `exo agent mount add "$AGENT" "$ROOT_DIR" "$SELF_REPO_MOUNT_PATH" --rw`. The exoharness storage root defaults to `.exo` (`crates/cli/src/main.rs:75`, `default_value = ".exo"`) — *under that mount* — and `SELF-CONTROL.md`'s own state table places "Conversation history + event log" at `.exo/exoharness`. No mount exclusions exist in `sandbox.rs`. The log's protection is the operating rule "preserve `.exo`" — a convention, and their own design principle names the failure mode: *"a mutation path that bypasses the tools also bypasses the record."* The regress we predicted from the podcast (immutability must live below the mutable boundary) is visible in one line of shell. Fairness: with a *remote* sandbox provider the host filesystem is genuinely out of reach — the flagship claim holds there, but the quickstart path is local Docker.

**2. The canonical history is not crash-durable.** Event and conversation writes are pretty-printed JSON through `object_store::LocalFileSystem` (`storage.rs`) with **no fsync and no locks** — `sync_all` appears only in `secrets.rs` and the Firecracker code. Contrast ADR 0015: O_EXCL, fsync of file and directory, single-writer lock with owner token, corrupt-tail-only tolerance. The line for the essay is now code-backed: **Exo asserts an immutable log; piko engineered one.**

**3. No hard budgets exist.** `max_tool_round_trips` is `Option<u32>` and the agent-sandbox path sets it to `None` (`agent_sandbox.rs:203`); `max_output_tokens` is optional per request; one round-budget bail exists in the RLM path. No wall-clock ceiling, no total-token ceiling, no spend ceiling. The `cost` crate is a *pricing table loader* (LiteLLM's public price DB) — accounting, not enforcement. For a fleet-of-50,000 pitch, the governor piko's ADR 0009 exists for is absent.

**4. Self-verification is thinner than the podcast implied — by their own admission.** `rebuild_and_restart_exo`'s "validate" is build-and-restart; `SELF-CONTROL.md` §8: the canary path ("run the changed build against a cloned sandbox … and compare behavior **before adopting it on the live instance, instead of validating on the only copy of itself**") is listed as a "gap worth closing eventually." Rollback triggers on *broken*; nothing measures *bad*.

**5. The exoharness HTTP API shows no server-side auth.** The client supports an optional bearer token defaulting to none; `http/server.rs` contains no authorization check we could find. The layer boundary appears to rest on network reachability — worth deeper verification before repeating publicly, but as read, the "narrow API" is narrow in verbs, not in callers.

## What piko should steal (concrete, cheap)

1. **The LiteLLM pricing-table loader pattern** (`crates/cost`): same public JSON DB, cache-with-TTL, degrade-to-empty. This directly closes ADR 0009's admitted gap ("monetary cost bounded only via token proxies until per-model pricing is wired") and gives `pi improve` its dollars-per-completed-task fitness metric. An afternoon of work.
2. **`SELF.md` — the checked-in self map.** A compact navigational guide to the codebase, told to the agent each run. For `pi improve`, this is cheap, high-leverage context. piko's map tool renders structure; a curated self-map adds intent.
3. **Drain-marker restarts** for any future long-running piko mode: write a marker, let the loop finish its turn and exit on its own terms, kill only on timeout — outcome journaled. It's 0007's ethos applied to process lifecycle.
4. **A `SandboxProvider` seam, not just Docker**: when the container executor lands, define the trait boundary the way they did (acquire/exec/snapshot verbs), so Firecracker or remote providers are additive later. Ship only Docker; design the seam.

## What this changes in the pivot memo

Nothing structural — it hardens it. The comparison essay's spine is now sourced: same tripartite cage, but their un-red box is convention + best-effort JSON where piko's is mechanism + fsync + locks; their referee is a build check on the live instance where piko's is fail-closed evals behind an approval. And their two admitted gaps — the canary path and (implicitly) budgets — are exactly the two components `pi improve` and ADR 0009 supply. The generous framing survives too: their sandbox layer and ops engineering are ahead of piko's, their docs culture is kin, and the executor-cartridge bridge remains real. Add one line to the memo's "Next" column: adopt the pricing-table loader now.

## Fairness notes

Shallow clone of main; no history reviewed, no issues/PRs read, HTTP auth deserves a second look before public claims. The project is young and its docs disclose several of these findings themselves — judge the honesty as generously as the gaps.
