The Agentic Harness Landscape

Where terminal coding harnesses stand in August 2026 — the leaders, the field, the measured evidence on harness efficiency, and where a sub-600-token clean-room build (piko) fits. Compiled from primary sources; unverifiable claims flagged or excluded.

01TL;DR

  • The harness now matters more than the model. The only controlled factorial (arXiv 2605.23950) measures harness-induced variance at 7.8× model-induced variance; under a fixed harness, frontier models sit within 2.5–5pp of each other. "Harness engineering" became a named discipline in 2026 (Fowler, Osmani, Weng all published on it).
  • Two leaders, converged at the top: Claude Code (83.8%) and Codex (83.1%) on Terminal-Bench 2.1 — but at wildly different economics ($553 vs $2,059 for the run) and opposite architectures (44 tools / 20–30k tokens session-start vs ~4–7 tools / 2–5k).
  • Token efficiency is now a measured battleground: equal-quality stacks differ by 1.65× tokens (Artificial Analysis); Claude Code carries ~33k tokens of pre-prompt overhead vs OpenCode's ~7k (Systima); a 66k-star product (Headroom) exists purely to compress harness waste.
  • The 2026 shake-out was brutal, and the vendor-CLI segment is collapsing: Gemini CLI killed for consumers (successor closed-source), Kimi CLI superseded, Qwen's free tier axed, Aider unmaintained, Roo Code archived. Model vendors are retreating from open CLIs as loss-leader distribution — and 2026 produced two separate demonstrations (the Gemini shutoff; Anthropic's January block on OpenCode) that a single upstream vendor can revoke a harness's economics overnight. Provider neutrality graduated from feature to risk control. Meanwhile interop (MCP + AGENTS.md + ACP) moved to neutral governance, commoditizing integration.
  • The lean thesis is validated but bounded: minimal harnesses win on cost at frontier-model tier (Harness-Bench's top scorer used the fewest tokens; Databricks measured 3× less context at >2× cost advantage) — but heavy scaffolding wins on weak models, and the fuller harness still wins raw capability benchmarks. Lean is a cost/inspectability bet, not a capability bet.

02Market structure: four layers, four segments

The 2026 stack has stratified. Models (increasingly interchangeable under a fixed harness) → harnesses (where the variance lives) → interop protocols (MCP, AGENTS.md — 60k+ repos, ACP — 25+ agents; all now neutrally governed under the Linux Foundation's AAIF or moving that way) → a genuinely new 2026 tier: fleet orchestrators (ruflo 68k★, Orca 48k★, Gastown 18k★…) that run many harnesses in parallel and are harness-agnostic.

Harnesses themselves segment four ways:

The structural tailwind for lean: fleet orchestrators multiply harness cost by N agents, so the swarm layer economically rewards cheap-per-task harnesses — Orca explicitly lists pi alongside Codex/Claude Code/OpenCode as runnable engines. And with integration commoditized by neutral protocols, context discipline is one of the few durable differentiators left.

The paradox worth naming: each leader embodies the other's counter-thesis. Codex proves a near-minimal tool surface can top benchmarks; Claude Code proves a maximalist harness can be cheaper per benchmark point (its models bill less per token). Neither is both lean and cheap — which is precisely the gap the minimal segment targets.

What users actually complain about (HN, 2026 — mined from the top threads)

  • Harness overhead went mainstream: the "Claude Code sends 33k tokens before reading the prompt" thread drew 706 points; commenters note the overhead persists per request ("10 requests = 330k tokens") and that runaway sub-agent spawns (one report: 171 spawned to verify one thing) exhaust plan quotas in single prompts.
  • Permission fatigue is universal: heavy users alias --dangerously-skip-permissions within a week ("I felt like Homer Simpson running the nuke plant"); approval prompts "won't scale" with parallel agents — evidence the per-call-prompt model is failing in practice, supporting the sandbox-instead position.
  • Compaction is distrusted: Codex's non-disableable auto-compaction with no pre-compact rollback is a stated switching reason ("a no-go for me"); users report models "briefly lost on where they are in the plan post-compaction." Observable, reversible compaction is a real differentiator, not a nicety.
  • Doom-loops burn budgets: "agents stuck in a loop, just burning tokens without any value" recurs across both tools' threads — including Uber reportedly torching its 2026 AI budget in four months. Flail-capping is an unserved need across the whole market.
  • The deepest grievance is invisible economics (GitHub-verified): Claude Code's cache TTL silently regressed 1h→5m (+20–32% cost, proven across 119,866 logged API calls, #46829); v2.1.100 billed ~20k more tokens per request than v2.1.98 on a smaller payload — spoofing the old user-agent restored baseline (#46917); Codex's per-token limit cost jumped 10–20× overnight (#28879, 559 reactions) and GPT-5.5's reasoning was silently truncated to exactly 516 tokens in 53% of responses by May (#30364). Users caught every one of these only by proxying their own traffic. The most-reacted issue in Claude Code's history (#42796, 3,286 reactions) is a quality-regression thread whose closure itself became a grievance. Auditable billing — a local ledger of every byte sent — is now a competitive feature, not a nicety.

05What the evidence actually supports

Verified (cite these)

  • Harness variance ≫ model variance: 7.8× (replications 8.7× / 6.8×), 6 of 9 model rankings reverse across harnesses; competent-scaffold swaps move the same model 9.5–15pp. arXiv 2605.23950
  • Harness-Bench (controlled, 5,194 trajectories): 23.8pp gap between best (nanobot 76.2%) and worst (52.4%) harness on identical tasks/models — and the winner used the fewest tokens. Cross-harness variance shrinks as models get stronger. arXiv 2605.27922
  • Equal quality, divergent economics: AA measures Claude Code and Codex at the same index (67) with 21.8M vs 13.2M tokens per task; production cache hit rates 97% vs 90%; one field case took a 7%→84% hit rate from prompt reordering alone for a 59% bill cut. artificialanalysis.ai
  • Fixed overhead is real money: ~33k (Claude Code) vs ~7k (OpenCode) tokens before the user types; MCP servers add 10–20k each (GitHub MCP ~42–55k); a 72KB instruction file adds ~20k per request. Systima via two secondaries; Anthropic official tool-token tables
  • Databricks (vendor-internal, directional): pi sent ~3× less context per turn; same model through different harnesses = >2× cost per task at unchanged quality. Per-harness pass rates were never published (the "highest pass rate" line is Earendil's own claim).
  • End-to-end fixed footprint, measured at the API boundary (Cdani, identical trivial prompt, Haiku 4.5): Claude Code 28,407 input tokens → OpenCode 12,374 → pi 2,768. Working-set discipline over a task is where the money is: openbench measured pi at 37.6k fresh tokens per solve vs Codex's 117k on the same model.

The caching inversion — the honest complication in the lean thesis. Anthropic's minimum cacheable prefix is model-dependent (512 tokens on Opus 5/Fable 5, 1,024 on Sonnet 5, up to 4,096 on Haiku 4.5); OpenAI's automatic caching also needs 1,024+. A sub-1,000-token fixed prefix therefore often cannot be cached at all, while a large prefix bills at 0.1× from turn two — in the Cdani measurement, OpenCode becomes cheaper per turn than pi in long sessions for exactly this reason. The advantage bites hardest on first turns, short sessions, and fleet fan-outs (many cold starts — which is also the swarm-layer case where lean wins biggest). Net: fixed-prefix size is a signal of context discipline and a proof of philosophy; the actual mechanism that saves money is per-turn working set, which is what Databricks and openbench measured. Lean harnesses should compete on cost-per-completed-task, not prompt-size bragging rights.

Debunked (retire these)

  • "16-point Cursor-vs-Claude-Code swing" and "36-point CORE-Bench swing" — rest on a 93% score exceeding every entry on the official boards; inconsistent attribution across sources.
  • "pi tops the Terminal-Bench leaderboard" — pi has no official TB submission at all (verified against all three boards; its Harbor adapter is dormant since Dec 2025).
  • SEO-tier TB scores in the 85–92% range attributed to harnesses — those are Artificial Analysis model rankings under the fixed Terminus 2 reference harness, a different board.
  • Vendor-submitted SWE-bench Verified numbers as model comparisons — 99 of 100 entries ran the vendor's own scaffold; they are model+harness composites.

06Where piko sits

piko (github.com/arunmenon/piko) is a clean-room ~3.1k-LOC implementation of the lean thesis: 4 tools, ~557 fixed tokens (CI-gated <1,000), zero runtime deps, JSONL-observable sessions, headless self-spawn as the sub-agent primitive, auto-compaction into new session files.

Honest position: piko is architecturally competitive with the lean segment's best on every measured axis, and is unusual in publishing its own adversarial benchmark including the result that its solve rate trails the benchmark-native reference (5/10 vs 7/10) even as its cost per clean solve is ~6× lower. What it is not: a product. No ecosystem, no distribution, one maintainer, 10-task evidence base. Its value is as a verified reference implementation of the lean thesis — and as leverage: 3.1k auditable lines that one person can fully understand and modify beats 512k leaked lines nobody can.

07Strategic read

  • The lean bet is the right bet for frontier models and fleets — every controlled measurement (Harness-Bench, AA, our own strong-model cell) shows minimal context winning on cost at equal-or-near quality as model capability rises, and the swarm layer multiplies that advantage by N.
  • But capability benchmarks still reward scaffolding. Claude Code tops TB2.1 with its 44 tools; LangChain's deepagents gained 13.7pp from harness engineering that ablations attribute to tools/middleware/memory, not prompt slimming. The intellectually honest lean pitch is cost + inspectability + auditability, not "matches capability everywhere."
  • Differentiation is migrating from integration surface (commoditized by MCP/ACP/AGENTS.md) to context discipline, cache engineering, and trust (Gemini CLI's closed-sourcing and the Kahn lawsuit made openness and predictable billing selling points).
  • Minimalism alone is an occupied position. Upstream pi holds it with 93k stars, Earendil funding, ~8.7M installs/month and a 3,682-package extension ecosystem — and its fastest-growing fork (oh-my-pi, 3,758 commits/30d) got there by rejecting minimalism. Sub-1k fixed tokens is table stakes and proof-of-philosophy, not the value proposition. The unclaimed adjacent axes: a single-binary Go/Rust minimal harness with an OSI license (pi and piko are both Node), the ~200-token MCP-proxy pattern (pi-mcp-adapter) instead of schema loading, and being the best cheap swappable backend behind meta-harnesses (Databricks' Omnigent treats Claude Code/Codex/pi as one-line-swappable — enterprises are commoditizing the harness).
  • For piko specifically: (1) keep the budget gate and observable-compaction as identity, but frame the headline metric as cost per completed task with published methodology, not prefix size (see the caching inversion); (2) flail-capping: shipped and measured — equal accuracy at 59% less spend on the benchmark re-run, the market's shared doom-loop complaint answered; (3) repo map: shipped — a zero-dep symbol map (5th tool, ~200 tokens to map a package) reviving Aider's abandoned context-supply idea; (4) an official Terminal-Bench 2.x submission via Harbor would make it one of very few lean harnesses with a verifiable public number — upstream pi never submitted; (5) adopt the MCP-proxy pattern if integrations are ever needed; (6) ACP support plugs into the editor layer cheaply; (7) provider neutrality and the local-model path are durability requirements now, not conveniences — piko already has both.

08What the blogs get wrong (verified corrections)

  • pi is by Mario Zechner (now at Earendil, with Ronacher and Steinberger) — not "by Armin Ronacher."
  • Qwen Code is not "just a Gemini CLI fork" — the maintainers formally stopped syncing at v0.1 and the feature surface has no Gemini CLI equivalent.
  • Terminal-Bench 1.0 scores ("Droid tops at 58.75%") are still quoted as current; the boards are not comparable across versions.
  • Gemini CLI's README still advertises a free tier that stopped serving on 2026-06-18.
  • "Codex is 4× more efficient" conflates tokens with dollars — on TB2.1 Claude Code was 3.7× cheaper at indistinguishable accuracy while plausibly using more tokens.
