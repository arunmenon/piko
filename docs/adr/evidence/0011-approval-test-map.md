# ADR 0011 clause-to-test map

Verified 2026-08-24 against the Phase 1 implementation. Test names are stable
evidence identifiers; CI runs them through `npm test`.

| ADR clause | Required property | Passing evidence |
|---|---|---|
| Decision 1 — policy and provenance | Default none; list and `"*"` policies; user config/profile inheritance; CLI override; project instructions cannot relax the explicit policy | `an unconfigured approval policy changes nothing: the gated-name tool just runs` (`packages/core/tests/approval.test.ts`); `approval gating is read from user config, per profile or as a default` (`packages/ai/tests/config.test.ts`); `parseArgs collects gated tool names from repeated and comma-separated values` and the trusted-project end-to-end suspension in `a gated tool suspends a headless run with exit 4, and a resume decision completes it` (`packages/cli/tests/approvals.test.ts`). The setup construction passes only user config/profile or `--require-approval` into `ToolExecutionPolicy`; extension exports and project content have no policy input. |
| Decision 2 — ordered suspension | Earlier ungated calls run; the first gate stops dispatch; later calls remain planned; no later model request; `approval_required` and `suspended` are emitted | `a gated call suspends the turn before dispatch and makes no further model request`; `ungated calls before the gate run in order; later calls stay planned`; `a partially decided batch runs in order and suspends again at the next undecided call` (`packages/core/tests/approval.test.ts`). |
| Decision 3 — durable decisions and edits | Approve/edit/reject rows are validated before append; original and edited arguments remain distinguishable; rejection reason and edit provenance reach the model | `journal rejects invalid approval transitions before appending anything`; `resume applies approve, edit, and reject and continues the turn`; `an edit with invalid arguments is refused before anything is journaled` (`packages/core/tests/approval.test.ts`); CLI `--edit` and rejection integration tests (`packages/cli/tests/approvals.test.ts`). |
| Decision 4 — crash windows and concurrency | requested→decided remains awaiting; decided→started dispatches once; started→terminal becomes outcome unknown; a second decider cannot acquire the session | `crash while awaiting approval: reopen keeps awaiting_approval and does not repair the batch`; `decided(approved) with no started row dispatches exactly once on resume`; `a started call with no terminal row is still outcome_unknown beside a pending approval` (`packages/core/tests/approval.test.ts`); `a concurrent approval decider is rejected by the session lock without journal mutation` (`packages/cli/tests/approvals.test.ts`). |
| Decision 5 — budgets across resume | Tool, token, and request accounting continue across suspension; inherited ceilings do not widen; explicit raises are journaled | `tool-call budget accounting spans suspension and still wins on resume`; `token accounting carries across a suspension so a resumed run cannot exceed its ceiling`; `a resumed run inherits the suspended ceilings and journals an explicit raise` (`packages/core/tests/approval.test.ts`). |
| Decision 6 — automation contract | Exit 4 means suspended; versioned JSON emits additive approval events and a typed suspended terminal; resume decisions use the same envelope | `a gated tool suspends a headless run with exit 4, and a resume decision completes it` and `a scripted REPL run reports the suspension and exits 4 instead of inventing an answer` (`packages/cli/tests/approvals.test.ts`). |
| Decision 7 — surfaces | Strict inline parser recognizes only approve/edit/reject; headless decisions are explicit flags; suspended REPL/script behavior is non-success | `the inline prompt never reads an unrecognized answer as approval`; `edited arguments must parse as a JSON object`; `parseArgs binds --reason and --args to the decision they follow`; `parseArgs rejects malformed or contradictory decision flags`; CLI suspension/resume integration tests (`packages/cli/tests/approvals.test.ts`). |
| 2026-08-24 addendum — compaction | Manual summaries and both compaction triggers refuse before provider or journal mutation while suspended | `pending approvals block manual and automatic compaction without mutating the session` (`packages/core/tests/approval.test.ts`). |

The map is complete only while every row names at least one passing automated
test and the addendum remains consistent with the implementation. A future ADR
that supersedes or amends 0011 must update this map in the same change.
